# 무신사 연동 — 무엇이 되고 무엇이 안 되는가

먼저 결론부터. **무신사에는 상품 조회용 공개 API 가 없습니다.**

## 공식 파트너 API 로 되는 것

무신사 파트너센터가 제공하는 API 는 **주문 연동 전용**입니다.

| 항목 | 내용 |
|---|---|
| 가능 | 주문 수집 |
| 불가능 | 상품 정보 조회, 상품 등록·수정 |
| 접근 조건 | 입점 계약 완료 후 파트너센터에서 API 인증키 발급 |
| 연동 방식 | 승인된 API 대행사(아르고) 경유. 대행사 최초 설정만 웹에서 가능 |

즉 **광고에 쓸 상품 정보를 API 로 가져올 방법이 없습니다.** 주문 데이터는
받을 수 있지만 그건 광고 세팅이 아니라 정산·CS 영역입니다.

## 그래서 이 앱이 쓰는 방법

### 1. 상품 페이지 파싱

공개된 상품 페이지의 Open Graph 태그와 JSON-LD(`schema.org/Product`)를 읽습니다.

```
https://www.musinsa.com/products/1234567
        ↓
{ name, brand, price, imageUrl, description }
```

인식하는 URL 형식 (무신사가 몇 번 바꿔서 전부 받아둡니다):

- `musinsa.com/products/1234567`
- `musinsa.com/app/goods/1234567`
- `musinsa.com/goods/1234567`
- `?goodsNo=1234567` 쿼리가 붙은 모든 주소
- 상품 번호만 (`1234567`)

어떤 형식으로 넣어도 `https://www.musinsa.com/products/{번호}` 로 정규화하고,
트래킹 파라미터는 걷어냅니다.

**이 방식의 한계:** 무신사가 페이지 구조를 바꾸면 값이 비어 옵니다. 그래서
파싱 실패는 예외로 터뜨리지 않고 `warning` 을 담아 돌려주며, UI 에서 직접
입력할 수 있게 해뒀습니다. 파싱이 아예 안 되더라도 광고 생성 자체는 막히지
않습니다.

### 2. UTM 으로 성과 구분

무신사 쪽 유입을 광고별로 구분하려면 UTM 을 붙이는 수밖에 없습니다.
설정 → 무신사 탭에서 정한 값이 광고 생성 시 자동으로 붙습니다.

| 파라미터 | 기본값 | 설명 |
|---|---|---|
| `utm_source` | `meta` | 유입 채널 |
| `utm_medium` | `cpc` | 유입 방식 |
| `utm_campaign` | 캠페인 이름에서 자동 생성 | 캠페인 구분 |
| `utm_content` | 헤드라인에서 자동 생성 | 소재 구분 |

같은 키가 이미 붙어 있으면 덮어씁니다. 링크를 여러 번 만들어도 파라미터가
중복되지 않습니다.

UTM 은 **서버에서 붙입니다.** 브라우저가 보낸 URL 을 그대로 믿지 않기 위해서입니다.

## 검토해 볼 만한 대안

지금 구조로 부족하면 이런 선택지가 있습니다.

**무신사 파트너센터 주문 데이터 + UTM 대조**
주문 API 로 받은 주문에 UTM 이 실려 오는지 확인이 필요합니다. 실려 온다면
광고별 실매출을 정확히 붙일 수 있습니다. 파트너센터에 문의해야 확인됩니다.

**자사몰 병행 운영**
자사몰이 있다면 거기에 메타 픽셀을 심어 Conversions API 로 전환을 직접 받는
쪽이 훨씬 정확합니다. 무신사는 남의 도메인이라 픽셀을 심을 수 없습니다.
현재 이 앱의 전환 최적화(`OUTCOME_SALES`)도 픽셀을 심을 수 있는 도메인이
있어야 제대로 동작합니다.

**무신사로만 보낸다면 트래픽 목표가 현실적**
픽셀을 심을 수 없으니 전환 데이터가 메타로 돌아오지 않습니다. 이 경우
`OUTCOME_SALES` 로 최적화해도 학습할 신호가 없습니다. 랜딩이 무신사뿐이라면
**트래픽 목표(링크 클릭 최적화)** 로 돌리고, 실제 매출은 무신사 파트너센터
통계와 UTM 으로 대조하는 편이 맞습니다.
